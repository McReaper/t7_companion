# The `gdt_*` MCP tools

Referenced from `plugin/skills/assets/SKILL.md` — read that file first. The t7kb MCP server reads and edits GDTs with the install's own rules as the schema: `deffiles/<type>.awi` for the fields APE declares, the techsetdef a `materialType` resolves to for a material's texture slots and category.

## What each tool is for

`t7kb:gdt_find` (where an asset is defined, duplicates, stock or not), `t7kb:gdt_get` (fields, inherited ones included), `t7kb:gdt_schema` (what APE declares for a type, read from its `deffiles/*.awi`; for a material, the texture slots and category its techset really has), and `t7kb:gdt_edit` — which copies a donor with its LOD paths cleared, escapes backslashes, refuses stock GDTs and a second asset of the same type and name, and validates ranges, combo values, color/vector shapes, `materialType`/`materialCategory` agreement and image semantics before writing (dry run by default). The hand-authoring traps in `SKILL.md` are what it guards against.

- **Combo values are checked even where APE builds the list in script** — `surfaceType`, the filter and tile modes, an image's `semantic`. A value no option and no stock GDT uses is an error; values the current `.awi` dropped but stock still uses (its `//legacy support` filter names, `<legacy>` gloss) are accepted, because they link.
- **`surfaceType` left on `<error>` is a warning, not silence.** `<error>` is the `.awi`'s first option, so APE's default; once the material reaches collision the linker stops with `doesn't have surfacetype set in Asset Manager` (community reports, t7kb 0.25–0.60; every one of a stock install's 20,659 materials sets a real one). Set `<none>` if it truly has none.
- **It writes what APE writes when a field changes, unless the same request sets that field.** A `glossSurfaceType` preset writes its `glossRangeMin`/`glossRangeMax` (the range is what the material gets — 406 stock materials keep a preset that disagrees with their range); an image's `semantic` sets `premulAlpha` and `streamable` (`effectMap` → 1 and 0, anything else → 0 and 1), as `image.awi`'s callback does.
- **An xmodel LOD that switches in no farther out than the one before it is a warning** — it is never drawn (APE marks it red; 22 stock xmodels do it and link).

- **A material with its own textures is one `gdt_edit` call:** pass `assets` with an `image` item per texture (`{"texture": "texture_assets/…/wall_n.tif", "material_type": "lit", "field": "normalMap"}` — the semantic comes from that techset slot, every other setting from the most common value among stock images of that semantic, and a missing or non-power-of-two texture is an error), then the material naming those images. Items apply in order and the file is written only if none has an error, so a half-made set never lands.
- **A derived asset's parent must be in the same GDT.** gdtdb resolves `"child" [ "parent" ]` only within one file (`GDT ParseError: … Parent Entity '<name>' does not exist in GDT` otherwise — every one of a stock install's ~17k derived assets follows this). So you can't derive from a stock asset: `copy_from` it into your own GDT. It also means removing a duplicate from a pack GDT orphans that pack's derived assets of it, even when another copy survives elsewhere.
- **Before building, `t7kb:gdt_check` the GDT.** It reports what would otherwise surface one link error at a time: a reference to an asset that's in no GDT or is the wrong type (an xmodel in a `colorMap`), an xmodel/xanim export or texture missing on disk, a missing parent, two definitions of the same type and name (names are per type: an image and a material may share one).
- **Before renaming or deleting an asset, `t7kb:gdt_refs` it** — every asset that names it in a field or derives from it. Material names baked into an `.xmodel_bin` aren't searched: a model's materials come from its export.
