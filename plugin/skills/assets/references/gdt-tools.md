# GDT rules the `gdt_*` tools enforce, which hold by hand too

Referenced from `plugin/skills/assets/SKILL.md` — read that file first. The t7kb MCP server reads and edits GDTs against the install's own rules (`deffiles/<type>.awi` for the fields APE declares, the techsetdef a `materialType` resolves to for a material's slots); each tool's description says what it does. These are the rules behind its refusals and warnings, which an edit by hand breaks just as silently.

- **A derived asset's parent must be in the same GDT.** gdtdb resolves `"child" [ "parent" ]` only within one file (`GDT ParseError: … Parent Entity '<name>' does not exist in GDT` otherwise — every one of a stock install's ~17k derived assets follows this). So you can't derive from a stock asset: copy it into your own GDT. It also means removing a duplicate from a pack GDT orphans that pack's derived assets of it, even when another copy survives elsewhere.
- **`surfaceType` left on `<error>` stops the link once the material reaches collision.** `<error>` is the `.awi`'s first option, so APE's default; the linker then stops with `doesn't have surfacetype set in Asset Manager` (community reports, t7kb 0.25–0.60; every one of a stock install's 20,659 materials sets a real one). Set `<none>` if it truly has none.
- **APE writes dependent fields when one changes.** A `glossSurfaceType` preset writes its `glossRangeMin`/`glossRangeMax` (the range is what the material gets — 406 stock materials keep a preset that disagrees with their range); an image's `semantic` sets `premulAlpha` and `streamable` (`effectMap` → 1 and 0, anything else → 0 and 1), as `image.awi`'s callback does. Change the preset or the semantic by hand and set those fields with it.
- **Combo values APE builds in script are still a closed list** — `surfaceType`, the filter and tile modes, an image's `semantic`: use one an option or a stock GDT uses. Values the current `.awi` dropped but stock still uses (its `//legacy support` filter names, `<legacy>` gloss) link.
- **An xmodel LOD that switches in no farther out than the one before it is never drawn** (APE marks it red; 22 stock xmodels do it and link).
- **A model's materials are in its `.xmodel_bin`**, as the linker reads them: APE's `materials` field on an xmodel is usually empty and can be stale, so look in the LOD files before renaming or deleting a material.
- **A material made from your own textures is one `t7kb:gdt_edit` batch**: an image per texture first, then the material naming them; the batch lands whole or not at all, so a half-made set never does.
